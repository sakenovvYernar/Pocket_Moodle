ТЕХНИЧЕСКОЕ ЗАДАНИЕ
Проект: AI University Assistant (Telegram Bot + Mini App)
________________________________________
1. Общая информация
1.1 Название проекта
AI University Assistant
________________________________________
1.2 Тип системы
Интеллектуальная информационная система для студентов университета, реализованная на базе:
•	Telegram Bot 
•	Telegram Mini App (Web Application) 
________________________________________
1.3 Цель проекта
Создание единой цифровой платформы, позволяющей студентам:
•	получать доступ к академическим событиям (расписание, дедлайны, квизы); 
•	получать уведомления; 
•	взаимодействовать с AI-ассистентом; 
•	просматривать учебную информацию в удобном интерфейсе Telegram. 
________________________________________
1.4 Основное назначение
Система предназначена для:
•	централизованного отображения учебных событий; 
•	автоматизации напоминаний; 
•	упрощения взаимодействия с университетскими данными; 
•	предоставления AI-помощника для студентов. 
________________________________________
2. Предметная область
В университетах учебные данные обычно распределены по нескольким системам:
•	LMS (например, Moodle); 
•	расписание занятий; 
•	система оценивания; 
•	календарь дедлайнов. 
В рамках проекта предполагается объединение всех событий через единый календарный источник (ICS формат) и их интеллектуальная обработка.
________________________________________
3. Архитектура системы
Система состоит из следующих компонентов:
________________________________________
3.1 Telegram Bot
Основной канал быстрого взаимодействия с пользователем.
Функции:
•	AI-чат; 
•	уведомления; 
•	быстрый доступ к расписанию и дедлайнам; 
•	запуск Mini App. 
________________________________________
3.2 Telegram Mini App
Веб-приложение внутри Telegram, предоставляющее расширенный интерфейс.
________________________________________
3.3 Backend Server
Серверная часть системы, отвечающая за:
•	обработку запросов; 
•	парсинг календаря (ICS); 
•	работу с AI; 
•	хранение данных; 
•	систему уведомлений; 
•	кэширование данных. 
________________________________________
3.4 AI Module
Интеграция с:
•	Google Gemini API 
________________________________________
3.5 Database
Используется:
•	Firebase Firebase Firestore 
________________________________________
4. Источник университетских данных (ключевое изменение)
4.1 LMS Calendar Integration (ICS)
Система получает данные из:
•	Moodle Calendar Export URL (ICS формат) 
Пример:
•	ссылка на календарь с событиями университета 
________________________________________
4.2 Типы получаемых данных:
•	расписание занятий; 
•	дедлайны; 
•	квизы; 
•	экзамены; 
•	академические события. 
________________________________________
4.3 Обработка данных:
Backend выполняет:
•	загрузку ICS файла; 
•	парсинг событий; 
•	классификацию событий; 
•	преобразование в JSON; 
•	сохранение в Firebase. 
________________________________________
4.4 Классификация событий (логика системы):
Система автоматически определяет тип события:
•	Lecture (занятие) 
•	Deadline (задание) 
•	Quiz (тест) 
•	Exam (экзамен) 
________________________________________
5. Функциональные требования
________________________________________
5.1 Telegram Bot
5.1.1 AI-чат
Пользователь может:
•	задавать вопросы; 
•	получать объяснения; 
•	получать информацию о расписании и дедлайнах. 
________________________________________
5.1.2 Уведомления
Система отправляет:
•	напоминания о занятиях; 
•	напоминания о дедлайнах; 
•	напоминания о квизах и экзаменах. 
________________________________________
5.1.3 Напоминания о занятиях
Отправка уведомлений:
•	за 30 минут до занятия; 
•	за 10 минут до занятия. 
________________________________________
5.1.4 Напоминания о дедлайнах
Примеры:
•	“Дедлайн Assignment сегодня” 
•	“Quiz начинается завтра” 
________________________________________
5.1.5 Команды бота:
•	/schedule 
•	/deadlines 
•	/ai 
•	/attendance 
•	/settings 
________________________________________
5.1.6 Запуск Mini App
Бот предоставляет кнопку открытия Web App.
________________________________________
5.2 Telegram Mini App
________________________________________
5.2.1 Главный экран
Отображает:
•	ближайшие пары; 
•	ближайшие дедлайны; 
•	уведомления; 
•	быстрый доступ к разделам. 
________________________________________
5.2.2 Модуль “Расписание”
Функции:
•	просмотр расписания; 
•	фильтрация по дням; 
•	отображение событий из календаря. 
________________________________________
5.2.3 Модуль “Дедлайны”
Функции:
•	список дедлайнов; 
•	сортировка по времени; 
•	статус выполнения. 
________________________________________
5.2.4 Модуль “Оценки”
Функции:
•	отображение оценок (если доступны через систему); 
•	GPA; 
•	средний балл; 
•	история. 
________________________________________
5.2.5 Модуль “Attendance Calculator”
Функции:
•	расчет посещаемости; 
•	допустимые пропуски; 
•	прогноз допуска. 
________________________________________
5.2.6 Модуль “AI Chat”
Функции:
•	чат с AI; 
•	контекст университета; 
•	сохранение истории. 
________________________________________
5.2.7 Модуль “Карта университета”
Функции:
•	отображение корпусов; 
•	поиск аудиторий; 
•	навигация. 
________________________________________
5.2.8 Модуль “Настройки”
Функции:
•	уведомления; 
•	язык; 
•	тема; 
•	настройки AI. 
________________________________________
6. Авторизация и подключение пользователя
________________________________________
6.1 Telegram Authentication
Пользователь идентифицируется через:
•	Telegram ID 
________________________________________
6.2 Подключение календаря (основной источник данных)
Пользователь вводит:
•	учебную группу; 
•	Moodle Calendar URL (ICS ссылка) 
________________________________________
6.3 Процесс подключения:
1.	Открытие Mini App 
2.	Ввод группы 
3.	Ввод Calendar URL 
4.	Проверка доступности ссылки 
5.	Парсинг ICS данных 
6.	Сохранение в Firebase 
________________________________________
6.4 Безопасность:
•	отсутствует пароль Moodle 
•	используется только календарный URL 
•	данные не изменяются системой 
•	токенизация и защита данных Firebase 
________________________________________
7. Обработка данных календаря (ICS)
________________________________________
7.1 Backend функции:
•	загрузка ICS файла; 
•	парсинг событий; 
•	нормализация данных; 
•	определение типа события; 
•	обновление кэша. 
________________________________________
7.2 Кэширование:
•	данные сохраняются в Firebase; 
•	обновление по расписанию (cron job); 
•	уменьшение нагрузки на источник. 
________________________________________
8. Нефункциональные требования
________________________________________
8.1 Производительность:
•	время ответа ≤ 2 секунд; 
•	поддержка ≥ 1000 пользователей; 
•	асинхронная обработка данных. 
________________________________________
8.2 Безопасность:
•	HTTPS; 
•	безопасное хранение данных; 
•	защита пользовательской информации; 
•	изоляция данных пользователей. 
________________________________________
8.3 Масштабируемость:
Система должна поддерживать:
•	разные университеты; 
•	разные LMS источники; 
•	расширение модулей; 
•	замену AI. 
________________________________________
8.4 UX/UI:
•	адаптивный интерфейс; 
•	mobile-first дизайн; 
•	минималистичный UI; 
•	темная тема.
